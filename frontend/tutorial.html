FIELD GUIDE

How to use GLIMPSE

This guide walks through the main workspace, from choosing a dataset to interpreting model disagreement and counterfactual suggestions.

Keep in mind

GLIMPSE is a research tool for exploring model behavior. Predictions are not certainties, and suggested changes are hypothetical model-based scenarios—not recommendations or guarantees.

01

Choose a dataset

Start on Home and select a topic. The available datasets represent different prediction tasks, such as diabetes, breast cancer, or credit-card repayment. Dataset choice determines which features, outcomes, and model outputs appear in the workspace.

Try this

Select a topic, then choose Try an example person to explore the map without entering your own values.

Choose a dataset →
02

Navigate the map

The Map workspace shows a two-dimensional view of the model landscape. Click a location to inspect the corresponding profile. Drag over a region to zoom, use the zoom controls to adjust the view, or reset the zoom to return to the broader picture.

  • Simple: inspect the simpler model's view.
  • Flexible: inspect the more flexible model's view.
  • Both: view them side by side to compare their patterns.

Map position is a visualization of the feature space, not a real-world geographic location. Nearby points in the visualization should not automatically be interpreted as causally or socially similar.

Open the map →
03

Interpret a prediction

After selecting a person or entering feature values, review the prediction summary and the model results. A predicted class is produced by a decision rule applied to a score; it is not a statement of certainty about what will happen.

Pay attention to the range of outputs from other well-performing models. A narrow range suggests the models are more aligned for this profile; a wider range indicates that plausible models give meaningfully different estimates.

Disagreement is information

Agreement among models does not prove a prediction is correct. Disagreement does show that the conclusion can depend on which reasonable model is used.

04

Explore counterfactual changes

The “What would change it” area explores changes to input features that could alter a model outcome. Review the quickest and safest options separately: they represent different optimization goals, not a guarantee that an action is feasible or beneficial in real life.

  • Read which features are allowed to change and which are fixed.
  • Use “What if…” controls to test alternative values.
  • Use “My plan” to inspect a proposed set of changes and compare it with the current profile.

Counterfactuals describe model behavior under a hypothetical input. They do not establish that changing a feature will cause a real-world outcome to change.

05

Compare two people

Open Compare to select a dataset and two profiles. The summary presents their model outputs side by side; the feature table emphasizes differences so you can see which inputs vary. Use the control to reveal values that are the same when you need the full picture.

A difference in prediction may reflect several feature differences together. The comparison view is descriptive and should not be read as proof that any single feature caused the outcome.

Open Compare →
06

Assumptions and limitations

  • Dataset scope: results reflect the data and labels available for the selected task; they may not generalize to other populations.
  • Model uncertainty: the displayed range summarizes a set of models, not every possible model or every source of uncertainty.
  • Feature constraints: actionable changes depend on assumptions about which values can change. Real-life constraints may be more complex.
  • Not causal advice: feature importance, model disagreement, and counterfactuals do not by themselves establish causal relationships.

Use the tool to formulate questions and inspect model behavior—not as the sole basis for a consequential decision.
